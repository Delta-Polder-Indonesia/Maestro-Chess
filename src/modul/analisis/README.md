# Modul Analisis — fondasi engine dan deteksi fase permainan

Modul ini bagian dari modular monolith, bukan layanan terpisah. Cakupan saat ini **hanya** daftar pilihan dan pembungkus worker `EngineCatur`, pemeriksaan WASM dan ukuran hash, serta deteksi fase permainan (`deteksiFase.js`). Parser, klasifikasi, adaptor `EngineAnalisis`, cache hasil analisis, buku, provider Mesin, komponen visual dan bagian Analisis lain tetap pada path masing-masing; tidak ada pemindahan massal atau perubahan skema data/cache.

## API, identitas, dan dependensi

- `mesin.js` adalah fasad ringan tanpa JSX dengan tujuh ekspor bernama: `DAFTAR_ENGINE`, `ENGINE_BAKU`, `cariEngine`, `EngineCatur`, `wasmSupported`, `wasmThreadsSupported`, dan `hashUntukEngine`.
- `fase.js` adalah fasad ringan tanpa JSX/React dengan delapan ekspor bernama: `FASE_PEMBUKAAN`, `FASE_MENENGAH`, `FASE_AKHIR`, `DAFTAR_FASE`, `isEndOpening`, `isEndMiddlegame`, `faseBerikutnya`, dan `papanDariFen`.
- `index.js` meneruskan kelima belas ekspor bernama dari `mesin.js` dan `fase.js`. Tidak ada ekspor default pada `mesin.js`, `fase.js`, `deteksiFase.js`, `engineCatur.js`, `cekWasm.js`, maupun `index.js`.
- `src/lib/engineCatur.js` tetap meneruskan tepat empat ekspor bernama awal langsung ke `engineCatur.js`; `src/halaman/Analisa/mesin/cekWasm.js` meneruskan tepat tiga ekspor bernama awal langsung ke `cekWasm.js`; `src/halaman/Analisa/mesin/fase.js` meneruskan tepat delapan ekspor bernama awal langsung ke `deteksiFase.js`. Semua path dalam registry modul yang sama berbagi identitas array, objek pilihan, fungsi, dan kelas, bukan salinan. Identitas satu registry tidak menjamin singleton lintas proses, bundle terisolasi, atau salinan modul dengan URL berbeda.
- Fasad `mesin.js` hanya memuat dua implementasi engine/WASM dan `src/lib/asets.js`; fasad `fase.js` hanya memuat `deteksiFase.js` dan `chess.js`. Keduanya maupun `index.js` tidak memuat React, JSX, provider, fitur lain, storage, atau adaptor `EngineAnalisis`. Impor dan konstruksi tidak membuat worker atau membaca kemampuan browser; worker dibuat ketika `mulai()` dipanggil.
- Lima pemanggil aplikasi menggunakan `mesin.js`: adaptor `src/halaman/Analisa/mesin/engine.js`, provider `konteks/mesin.jsx`, pengaturan `komponen/pengaturan/mesin.jsx`, `komponen/nav/layarEngine.jsx`, dan `komponen/nav/layarDeteksiEngine.jsx`.
- Empat pemanggil aplikasi menggunakan `fase.js`: `komponen/menu/analysis/summary/playersAccuracy.jsx`, `komponen/nav/ringkasanAntiCheat.jsx`, `mesin/antiCheat/agregat.js`, dan `mesin/antiCheat/skor.js`. Tidak ada context, provider, atau hook baru; `KonteksMesin`, `useMesin`, dan `MesinProvider` mempertahankan identitas dan lokasi Tahap 11. Provider masih menggunakan `EngineAnalisis` pada path lama; modul Sesi tidak mengimpor modul Analisis maupun implementasi engine lama.

## Kontrak lama yang dipertahankan

- Enam objek pilihan tetap berurutan dengan ID, label, Elo, keterangan, URL, dan Stockfish 18 Lite sebagai default yang sama. URL dibentuk saat modul dimuat menggunakan base path saat itu. `cariEngine` memakai pencocokan ID ketat dan mengembalikan objek asli, bukan salinan; ID yang tidak dikenal memilih default.
- Array dan objek pilihan tetap dapat dimutasi. Bila ada ID duplikat, pencarian memilih entri pertama; jika objek default telah dihapus, fallback dapat menghasilkan `undefined`. Ini adalah perilaku lama, bukan validasi atau jaminan bahwa daftar boleh diubah oleh fitur baru.
- `EngineCatur` menyimpan state per instance dan memuat worker secara malas. Panggilan startup berbagi promise, mengirim perintah UCI awal dengan opsi NNUE untuk Stockfish 16, serta dapat dicoba kembali setelah gagal. Pesan `readyok` sendiri masih menyelesaikan startup sekalipun `uciok` belum diterima. `setop()` menolak permintaan tertunda dan mengirim `stop` untuk pencarian aktif; pencarian aktif masih menunggu `bestmove` atau galat/terminasi. Antrean, parser info/MultiPV, callback, pembersihan dan pesan galat tetap seperti implementasi lama.
- `wasmSupported` meneruskan hasil validator dan galat yang dilemparkannya. Jika global `WebAssembly` bernilai `null`, ia tetap melempar `TypeError`. `wasmThreadsSupported` tetap memeriksa kemampuan memori bersama tanpa menjadikannya syarat engine single-thread. `hashUntukEngine` tetap memilih 16 MB untuk perangkat seluler atau memori numerik hingga 2 GiB dan 32 MB pada kondisi desktop/default yang dikarakterisasi; `navigator` bernilai `null` tetap melempar. Temuan ini dicatat, bukan diperbaiki diam-diam.
- `DAFTAR_FASE` mempertahankan urutan `["opening", "middlegame", "endgame"]` dan tetap berupa array yang dapat dimutasi. `isEndOpening` mempertahankan ambang pengembangan asimetris pada baris awal putih dan hitam, `isEndMiddlegame` mempertahankan batas jumlah perwira/menteri/benteng, `faseBerikutnya` hanya melangkah satu tahap ke depan (`opening → middlegame → endgame`) dan mengembalikan input apa adanya bila papan kosong atau nilai fase tidak dikenal, serta `papanDariFen` mengembalikan `null` untuk FEN kosong atau tidak valid. Pemanggil tetap mempertahankan perbedaan perilaku lamanya pada langkah paksa di batas fase.

## Pengujian dan batas

`tests/analisa-fondasi-mesin-karakterisasi.test.mjs` dan `tests/analisa-fase-karakterisasi.test.mjs` dijalankan terhadap implementasi pada path asli sebelum migrasi dan tetap menguji path kompatibilitas. `tests/analisa-fondasi-mesin-batas.test.mjs` dan `tests/analisa-fase-batas.test.mjs` memeriksa ekspor dan identitas, graf fasad, definisi tunggal, pemanggil, impor server, serta batas modul. Tes lainnya menjalankan keenam engine sebenarnya melalui UCI di proses Node, termasuk NNUE; karakterisasi kelas menggunakan Worker tiruan, dan karakterisasi komponen fase menggunakan React Test Renderer serta terjemahan/provider tiruan. Ini bukan verifikasi browser Worker, visual, jaringan nyata, atau data pengguna. Pemeriksaan import statis tidak membuktikan semua URL runtime atau cabang browser.
