# Modul Sesi — Tab Kerja, preferensi, galat, titipan, impor, panel, Board dan Analyze

Modul ini bagian dari modular monolith, bukan layanan terpisah. Cakupannya saat ini adalah model/provider Tab Kerja; penyimpanan pengaturan, daftar tema papan, context dan provider konfigurasi Analisa; context/provider galat, helper pesan dan titipan PGN; context/provider impor; context status panel dan hook dropdown; tiga context, tiga hook, dan provider Board; serta context dan provider gabungan Analyze. Mesin, komponen visual, dan bagian Sesi lainnya belum dipindahkan.

## API dan kompatibilitas

- `src/modul/sesi/index.js` adalah fasad utama: ia mengekspor API model, `TabKerjaProvider`, `useTabKerja`, seluruh API preferensi, galat, titipan, impor, panel, Board dan Analyze, serta provider bernama `ConfigContextProvider`, `ErrorsContextProvider`, `ImportProvider`, `BoardProvider`, dan `AnalyzeContextProvider`.
- `src/modul/sesi/model.js` adalah fasad model tanpa JSX. `src/modul/sesi/preferensi.js` adalah fasad preferensi tanpa JSX: ia mengekspor `bacaAngka`, `bacaBoolean`, `bacaTeks`, `cobaBacaTeks`, `tulis`, `tulisBoolean`, `boardThemes`, `ConfigContext` dan `defaultUsedRatings`.
- `src/modul/sesi/galat.js` adalah fasad tanpa JSX untuk `ErrorsContext`, `pushPageError` dan `pushPageWarning`; `src/modul/sesi/titipan.js` untuk `KUNCI_PGN_TITIPAN`, `adaPgnTitipan` dan `ambilPgnTitipan`. Kedua entry tersebut dapat diimpor Node tanpa loader JSX dan tidak memuat Pekerjaan atau provider; fasad galat tetap memakai React untuk context.
- `src/modul/sesi/impor.js` adalah fasad tanpa JSX untuk `ImportContext` dan `useImport`; ia hanya memuat React dan context impor, bukan Pekerjaan atau provider lain. `src/modul/sesi/imporProvider.js` menyediakan `ImportProvider` bernama tanpa memuat Tab Kerja atau provider Sesi lain; provider ini memakai Pekerjaan dan titipan seperti sebelumnya.
- `src/modul/sesi/panel.js` adalah fasad tanpa JSX untuk `PanelAktifContext`, `useDropdown`, dan `tekanPanahOpsi`; ia hanya memuat dua implementasi tersebut dan React, bukan Pekerjaan atau provider Sesi lain. Provider panel tetap `PanelAktifContext.Provider` bawaan React, bukan provider terpisah.
- `src/modul/sesi/papan.js` adalah fasad tanpa JSX untuk `BoardContext`, `TampilanContext`, `SetTampilanContext`, `useBoard`, `useTampilan`, dan `useSetTampilan`. Fasad ini hanya memuat implementasi context dan React, bukan Pekerjaan atau provider. `src/modul/sesi/papanProvider.js` menyediakan `BoardProvider` bernama tanpa memuat barrel utama, Pekerjaan, atau provider Sesi lain; ia memakai i18n, preferensi, dan normalisasi pemain serta konstanta layar internal Sesi.
- `src/modul/sesi/analisa.js` adalah fasad tanpa JSX untuk `AnalyzeContext`, `TAMPILAN_ANALISA`, dan `normalisasiPemain`; ia hanya memuat implementasi context dan React, bukan Pekerjaan atau provider. `src/modul/sesi/analisaProvider.js` menyediakan provider **default** tanpa memuat barrel utama atau Tab Kerja. Provider menyusun Board dan Import, sehingga tetap membawa i18n dan fasad Pekerjaan melalui provider yang sudah ada; fasad utama mengekspor fungsi yang sama dengan nama `AnalyzeContextProvider`.
- Pemanggil aplikasi menggunakan fasad utama atau entry provider khusus, serta fasad ringan untuk API yang tidak memerlukan JSX. Path lama `src/halaman/Analisa/tabKerja.js`, `konteks/tabKerja.jsx`, `penyimpanan.js`, `komponen/pengaturan/boardThemes.js`, `konteks/configKonteks.js`, dan `konteks/config.jsx` tetap ada sebagai re-export kompatibilitas. Keempat shim preferensi meneruskan langsung ke implementasi pindahan agar tidak memuat dependensi fitur lain; `config.jsx` mempertahankan ekspor default provider.
- Path lama `src/halaman/Analisa/komponen/errors/pushPageError.js`, `konteks/errorsKonteks.js`, `konteks/errors.jsx`, dan `src/lib/titipanAnalisa.js` juga tetap menjadi re-export langsung; `errors.jsx` mempertahankan ekspor default. Pemanggil di dalam modul Sesi menggunakan implementasi titipan secara internal.
- Path lama `src/halaman/Analisa/konteks/importKonteks.js` dan `konteks/import.jsx` meneruskan langsung ke implementasi impor yang sama; keduanya mempertahankan ekspor bernama aslinya, tanpa menambahkan ekspor default. Pemanggil aplikasi memakai fasad impor ringan atau fasad provider sesuai kebutuhannya.
- Path lama `src/halaman/Analisa/konteks/panelAktif.js` dan `src/halaman/Analisa/komponen/nav/useDropdown.js` meneruskan langsung ke implementasi yang sama, dengan ekspor bernama aslinya tanpa ekspor default. Tiga pemanggil aplikasi menggunakan fasad panel; komponen visual `SelectDaftar`, `DropdownPilih`, dan `MenuKolom` tetap di tempatnya.
- Path lama `src/halaman/Analisa/konteks/boardKonteks.js` dan `konteks/board.jsx` juga meneruskan langsung ke implementasi Board yang sama, tanpa menambahkan ekspor default. Lima pemanggil context di luar Sesi memakai fasad ringan; provider Analyze dan Tab Kerja memakainya secara internal. Komponen visual tetap di tempatnya.
- Path lama `src/halaman/Analisa/konteks/analyzeKonteks.js` meneruskan tepat tiga ekspor bernama ke implementasi yang sama, sedangkan `konteks/analyze.jsx` tetap meneruskan hanya provider default. Sebelas pemanggil context aplikasi memakai fasad ringan dan `Analisa.jsx` memakai entry provider default; Board dan Tab Kerja memakai context internal. Tidak ada hook Analyze baru.
- Tidak ada implementasi atau context kedua: fasad dan path lama melihat identitas fungsi, `ConfigContext`, `ErrorsContext`, `ImportContext`, `PanelAktifContext`, ketiga context Board, `AnalyzeContext`, konstanta layar, array `boardThemes`, objek `defaultUsedRatings`, provider dan hook yang sama dalam satu registry modul. State tetap terpisah untuk setiap instance provider atau hook, bukan singleton global; penghitung kunci pesan galat tetap satu per registry modul.
- Dependensi keluar modul mencakup `react`, fasad Pekerjaan, dan i18n. Titipan PGN internal Sesi dan provider impor memakai fasad Pekerjaan seperti sebelum dipindah. Dependensi Board dan Tab Kerja ke context Analyze kini berada di dalam Sesi; kode mesin dan komponen visual tidak dipindahkan. Implementasi preferensi, galat, titipan, context impor, panel/dropdown, context Board, dan context Analyze tidak bergantung pada fitur lain di luar Sesi.

## Kontrak Tab Kerja

- Kunci `sessionStorage` tetap `maestro-analisa-tab-v1`; envelope JSON tetap `{ versi: 1, daftar, aktifId }`. Pembaca memeriksa versi dan ID aktif, menyaring ID/layar yang tidak sah serta duplikat, menormalkan akun dan penunjuk laporan/draf, dan memulihkan tujuan papan sesi lama seperti sebelumnya.
- Penulis menserialisasi objek tab yang diberikan apa adanya di dalam `daftar`; ia **tidak** menyaring field ekstra pada objek tersebut. Pembaca kemudian hanya memproyeksikan field yang dikenal. Perilaku ini dikarakterisasi dan dipertahankan, bukan jaminan bahwa setiap objek input hanya berisi penunjuk.
- Saat ada sesi tersimpan, penulisan ditunda sampai pemulihan selesai. Jika ada PGN titipan, tab baru ditambahkan dengan pilihan akun tab aktif tanpa menghapus PGN titipan. Pilihan akun dan penunjuk tab tetap terpisah; penghapusan akun bersama membersihkan pilihan yang cocok.
- `siapkanImpor` menginisialisasi Pekerjaan, memakai penunjuk draf pilihan atau fallback lama, dan membuat ID lain bila fallback sedang dipakai tab lain. Permintaan `bukaImpor` yang tidak lagi sesuai navigasi tidak membuka layar setelah inisialisasi selesai; kegagalan inisialisasi tetap diteruskan ke pemanggil.
- Jika penyimpanan tidak tersedia, sesi tetap dapat digunakan di memori dan status ketersediaan mencerminkan kegagalan. Kegagalan penyimpanan tidak menjamin data tersimpan; percobaan berikutnya terjadi saat state sesi berubah. Tidak ada sinkronisasi baru antar-tab browser.
- `perbaruiTab` mempertahankan identitas objek lama bila field yang dibandingkannya tidak berubah, termasuk jika hanya field ekstra yang diberikan. Ini perilaku lama, bukan perbaikan validasi.

## Kontrak preferensi

- Pengaturan menggunakan `localStorage` dengan awalan `maestro-analisa-`. `bacaTeks` tetap membaca kunci lama yang dikenal sebagai fallback bila kunci baru tidak ada, tanpa menulis ulang atau menghapusnya. Khusus `usedRatings` lama yang berisi 11 bit, bit ketiga digandakan saat dibaca; nilai pada kunci baru tidak dikonversi.
- `cobaBacaTeks` hanya memeriksa kunci baru dan membedakan nilai yang tidak ada dari kegagalan akses. Pembacaan angka, boolean, konversi string, nilai bawaan dan pelaporan kegagalan penyimpanan tetap seperti sebelumnya; `tulisBoolean` tetap tidak mengembalikan hasil `tulis`.
- Urutan/nilai tema dan rating, objek rating bawaan yang dapat dimutasi, serta identitas context dipertahankan. Provider membaca preferensi ketika di-mount; setter hanya mengubah state provider, sedangkan penyimpanan perubahan dilakukan oleh komponen yang sudah bertanggung jawab. Remount membaca nilai tersimpan lagi.

## Kontrak galat dan titipan PGN

- `pushPageError` dan `pushPageWarning` adalah fungsi async yang memanggil setter segera dan mengembalikan Promise; warning memakai `persisten: false` secara bawaan. Keduanya berbagi penghitung modul. Updater yang dijalankan belakangan tetap membaca penghitung saat updater dieksekusi, sehingga beberapa pesan dapat memperoleh kunci yang sama; perilaku lama ini tidak diubah.
- `ErrorsContext` memiliki nilai bawaan dengan daftar kosong dan setter no-op. Setiap provider memiliki daftar dan setter sendiri; remount mengosongkan daftar, tetapi tidak mereset penghitung modul. Komponen tampilan dan timer tetap di tempatnya.
- Titipan menggunakan kunci `sessionStorage` yang sama, `maestro-analisa-impor-awal`, dengan string PGN apa adanya. `adaPgnTitipan` hanya membaca. `ambilPgnTitipan` membaca lalu menghapus nilai nonkosong; nilai kosong tidak dihapus. Gagal mengakses storage atau `getItem` ditangani diam-diam. Jika `removeItem` gagal, pengambilan juga mengembalikan string kosong meski sempat membaca nilai; keadaan storage selanjutnya bergantung pada operasi yang gagal.

## Kontrak state impor

- `ImportContext` menyediakan enam pasangan `[nilai, setter]`: `data`, `pageState`, `progress`, `analyzeController`, `analyzingMove`, dan `langkahSementara`. Di luar provider, nilai bawaannya netral dan setter adalah no-op; satu `AbortController` bawaan dibagi oleh pemakai nilai default dalam registry modul.
- Setiap `ImportProvider` memiliki state dan controller sendiri. Saat mount, ia membuat satu ID pekerjaan dan memulai `data` sebagai `{ format: "fen", string: "", pekerjaanId, awalPekerjaan: true }`. `pageState` awal adalah `loading` bila ada titipan PGN nonkosong, selain itu `default`; keberadaan titipan hanya dibaca saat mount, tidak dikonsumsi oleh provider. Mengganti controller tidak otomatis meng-abort controller lama.
- `setData` tetap memanggil `simpanLaporanAktif`, membuat ID baru, lalu membaca snapshot Pekerjaan **sebelum** memproses updater. Urutan dan efek ini juga terjadi bila nilai baru falsy atau sama dengan objek sebelumnya. ID baru dan referensi record papan kosong dari snapshot ditentukan per pemanggilan, termasuk ketika updater dijalankan belakangan; snapshot tidak disalin mendalam. Kegagalan sinkron dari ketiga operasi tersebut tetap diteruskan.
- Untuk nilai baru yang dipakai, `pekerjaanId` eksplisit dipertahankan kecuali `null`/`undefined`; bila tidak diberikan, ID papan aktif berstatus `baru` dipakai ulang hanya jika cocok dengan ID data sebelumnya, dan selain itu dipakai ID baru. Nilai eksplisit seperti string kosong, nol, atau `false` tetap diterima seperti sebelumnya, bukan validasi baru. Penyimpanan laporan tetap tanggung jawab Pekerjaan dengan format dan kunci lamanya.

## Kontrak panel dan dropdown

- `PanelAktifContext` bernilai `true` di luar provider. `areaKerja` memberikan nilai aktif pada provider React yang sama untuk tiap panel; masing-masing pemanggilan `useDropdown` memiliki state terbuka, refs, dan ID daftar sendiri. Setiap instance menjaga setter, refs, dan ID tetap stabil selama mount.
- Listener `mousedown` tanpa capture dan `keydown` dengan capture hanya dipasang saat panel aktif dan dropdown terbuka, lalu dilepas ketika kondisi berubah atau hook unmount. Klik di luar dan blur ke luar menutup dropdown; klik atau blur ke dalam tidak menutupnya. Perubahan panel menjadi tidak aktif juga menutup dropdown.
- Perilaku lama tetap berlaku: jika dropdown dibuka secara eksplisit ketika panel **sudah** tidak aktif, state dapat tetap terbuka tanpa listener global sampai state atau status panel berubah. Tidak ada validasi atau perbaikan baru pada tahap ini.
- `ArrowDown`/`ArrowUp` pada pemicu membuka daftar dan memfokuskan opsi terpilih, atau opsi pertama jika tak ada yang terpilih; aktivasi keyboard menghasilkan fokus yang sama, sedangkan klik pointer tidak otomatis memindah fokus. Pada daftar, panah melingkar, `Home`/`End` menuju awal/akhir, dan jika fokus belum ada di opsi, kedua panah memilih opsi pertama.
- `Escape` pada listener capture hanya menutup dropdown jika panel tidak tersembunyi dan tidak ada alert dialog terbuka. Ia mencegah default tanpa menghentikan propagasi dan mengembalikan fokus ke pemicu hanya jika fokus ada di dalam wadah. `tutupDanFokus` tetap memfokuskan pemicu walaupun dropdown sudah tertutup.

## Kontrak Board

- `BoardContext` menyediakan empat belas pasangan `[nilai, setter]` dan `gameController`; `TampilanContext` dan `SetTampilanContext` memisahkan nilai layar dari setter. Di luar provider, nilai default tetap netral, setter dan perintah adalah no-op, dan pemain kosong dibekukan seperti sebelumnya. Di dalam provider setiap instance mempunyai state, setter, dan controller sendiri; identitas controller stabil selama mount.
- Nama pemain kosong dinormalisasi memakai terjemahan saat ini; field tambahan dan Elo nol dipertahankan. Kedalaman dibaca sekali saat mount dari `maestro-analisa-kedalaman` dengan fallback kunci lama `depth`, default 13, lalu dibulatkan dan dibatasi ke 6–20. Setter kedalaman selanjutnya tidak membatasi nilai dan provider tidak menuliskannya ke storage.
- Navigasi utama dan variasi memakai ref yang diperbarui oleh effect. Navigasi kembali ke awal garis kustom FEN satu posisi mempertahankan garisnya, sedangkan variasi PGN keluar ke garis utama; flags arah, animasi dan gerakan yang dikembalikan tetap seperti implementasi sebelumnya. `play`, `pause` dan `togglePlay` hanya mengubah state bermain.
- Perilaku lama dipertahankan, bukan diperbaiki diam-diam: `last()` pada game kosong menetapkan nomor langkah `-1`. Beberapa perintah dalam satu batch dapat membaca ref sebelum effect memperbaruinya; misalnya dua `forward()` dapat melampaui posisi utama terakhir.

## Kontrak Analyze

- Di luar provider, `AnalyzeContext` menyediakan 21 pasangan `[nilai, setter]` dan `gameController` dengan setter/perintah no-op; pemain kosong dibekukan, dan satu `AbortController` default dibagi di dalam registry modul. `TAMPILAN_ANALISA` tetap dibekukan. Provider default menyusun Board di luar Import, lalu meneruskan ke `AnalyzeContext` empat belas pasangan dan controller Board, enam pasangan Import, serta state `akun` miliknya sendiri; navigasi layar tetap terpisah.
- Identitas pasangan dari Board/Import dipertahankan pada nilai gabungan. Perubahan papan, impor, atau akun membuat nilai gabungan baru; navigasi layar saja tidak. Setiap mount provider memiliki akun, state Board/Import, dan controller sendiri. Remount mereset akun dan membuat controller impor baru, tetapi tidak meng-abort controller lama; PGN titipan tetap hanya dibaca, tidak dikonsumsi.
- `akun` awal tetap `{ platform: "chessCom", username: "" }`. Setter masih menerima nilai arbitrer atau fungsi updater tanpa validasi dan tidak menyimpan ke storage. `normalisasiPemain` tetap menghasilkan dua objek baru, memangkas dan mengonversi nama ke string, mempertahankan field ekstra secara dangkal dan Elo non-nullish termasuk nol, serta memakai `NOELO` bila Elo nullish. Fallback nama yang truthy tetap dapat berupa nilai non-string; getter yang melempar tetap meneruskan galat. Ini perilaku lama, bukan validasi baru.

## Pengujian

Tes karakterisasi `tests/analisa-sesi-*-karakterisasi.test.mjs` dijalankan terhadap implementasi asli sebelum pemindahan dan tetap menguji path kompatibilitas. `tests/analisa-sesi-batas.test.mjs`, `tests/analisa-sesi-preferensi-batas.test.mjs`, `tests/analisa-sesi-galat-titipan-batas.test.mjs`, `tests/analisa-sesi-impor-batas.test.mjs`, `tests/analisa-sesi-panel-batas.test.mjs`, `tests/analisa-sesi-board-batas.test.mjs`, dan `tests/analisa-sesi-analyze-batas.test.mjs` memeriksa ekspor, identitas, batas dependensi dan pemanggil; tes siklus memeriksa graf source seluruh aplikasi. Pengujian memakai React Test Renderer, transpile JSX dan storage/Pekerjaan atau document tiruan; satu uji impor memakai singleton Pekerjaan asli dengan IndexedDB simulasi. Ini bukan pengujian browser atau data pengguna nyata.
